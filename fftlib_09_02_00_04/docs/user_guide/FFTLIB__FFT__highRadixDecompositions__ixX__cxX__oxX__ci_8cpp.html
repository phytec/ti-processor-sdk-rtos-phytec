template<typename dataType >
FFTLIB_STATUS FFTLIB_FFT_highRadixDecompositions_ixX_cxX_oxX_twGen ( const FFTLIB_FFT_highRadixDecompositions_ixX_cxX_oxX_InitArgs *  pKerInitArgs,
void *restrict  pW,
const FFTLIB_bufParams1D_t *  bufParamsW 
)

This is a utility function that generates the computational matrices (DFT and twiddle factor matrices).

Of the data generated by this function, a part is written into the buffer pointed to by the pointer pW, while the other part is written into the FFTLIB_FFT_twData buffer. FFTLIB_FFT_twData must be mapped to L1D memory for optimal performance. The buffer pointer pW must also be passed as a parameter to FFTLIB_FFT_highRadixDecompositions_ixX_cxX_oxX_exec function.

Parameters
[in]pKerInitArgs: Pointer to the structure holding init parameters
[in]pW: Pointer to buffer holding the computational matrices
[in]bufParamsW: Pointer to the structure containing dimensional information of computational matrices' buffer

This function is the main execution function for the C7x implementation of the kernel. The function declaration conforms to the declaration of FFTLIB_FFT_highRadixDecompositions_ixX_cxX_oxX_exec.

The kernel is the optimized implementation for the Discrete Fourier Transform (DFT) computation using the C7x and MMA resources. The FFT size (number of FFT coefficients) is assumed to be greater than or equal to (MMA vector width)*2, and is assumed to be a power of 2.

DFT computation involves multiplication of the data vector by the DFT matrix. Our algorithm for DFT computation uses a factorization of the DFT matrix into sparse matrices to carry out the computation efficiently.

The following diagram illustrates the factorization of an example DFT matrix. A \( 16 \)-point DFT matrix is taken as an example, and its factorization using a decomposition factor of \( 4 \) into a product of three sparse matrices is shown. In the following diagram:

  • each matrix is bordered by edge rows/columns showing the column/row indices.
  • the values in each matrix cell indicate exponent of \( \omega \). Thus, \( 0 \) actually indicates \( \omega^0 = 1 \).
  • An empty matrix cell indicates a value of \( 0 \) in the cell.

The last row shows the result of factorization. Here, the right-most matrix is the sparse decomposition matrix which is a square block matrix and each block is a diagonal matrix, the matrix is the middle is a block diagonal matrix where each block is the \( 4 \)-point DFT matrix, and the left-most matrix is the permutation matrix. Now, instead of multiplying the data vector by the original \( 16 \)-point DFT matrix, we can multiply it in turn by the sparse decomposition matrix, the block diagonal DFT matrix and the sparse permutation matrix. Multiplication by the sequence of sparse matrices is often computationally more efficient than multiplying by the original dense matrix. After decomposition, if the DFT size in each block of the block diagonal DFT matrix is still too large to compute efficiently by direct matrix multiplication, the block diagonal DFT matrix is itself further decomposed (factorized) into a product of sparse matrices. The decomposition continues through a sequence of stages until the DFT size is small enough.

In our implementation, if the size of the input data vector is a power of MMA vector width/2, a decomposition factor of MMA vector width/2 is used in each decomposition stage. If the size of the input data vector is not a power of MMA vector width/2, a decomposition factor less than MMA vector width/2 is used for the very first decomposition stage, while the subsequent decomposition stages just use a decomposition factor of MMA vector width/2. The decomposition continues through stages until the DFT size is equal to MMA vector width/2. A decomposition factor of MMA vector width/2 and the final DFT size of MMA vector width/2 are chosen because the data used is complex (with real and imaginary parts), and MMA vector width/2 number of data points occupy a full MMA vector width.

We use the following notations to capture example factorizations in mathematical expressions:

  • \( \mathbf{F}_{N} \) indicates an \( N \)-point DFT matrix of size \( N\times N \). In the above diagram, the \( 16 \)-point DFT matrix shown is \( \mathbf{F}_{16} \).
  • \( \mathbf{P}_{N} \) indicates the permutation matrix of size \( N\times N \). In the above diagram, the sparse permutation matrix shown is \( \mathbf{P}_{16} \).
  • \( \mathbf{D}_{M,N} \) indicates the sparse decomposition matrix with \( M\times M \) blocks, and each block is an \( N\times N \) diagonal matrix. In the above diagram, the sparse decomposition matrix shown is \( \mathbf{D}_{4,4} \).
  • \( \mathbf{A}^{k} \) indicates a square matrix \( \mathbf{A} \) replicated block diagonally \( k \) times to form a block diagonal matrix. In the above diagram, the block diagonal DFT matrix shown is \( (\mathbf{F}_4)^4 \).
  • \( \mathbf{R}_N \) is used to denote the product of all permutation matrices in the final decomposition of \( \mathbf{F}_N \).

In the following examples, a MMA vector width of \( 32 \) is assumed so that the decomposition stages continue until the DFT size is equal to \( 16 \) - that is, until the DFT matrix block in the block diagonal DFT matrix is of size \( 16\times 16 \).

Factorization of \( 256 \)-point DFT matrix:

\( \begin{aligned} \mathbf{F}_{256} & = \mathbf{P}_{256}\left(\mathbf{F}_{16}\right)^{16}\mathbf{D}_{16,16} & \mbox{(decomposition stage 1)} \\ & = \mathbf{R}_{256}\left(\mathbf{F}_{16}\right)^{16}\mathbf{D}_{16,16} & \end{aligned}\)

Factorization of \( 512 \)-point DFT matrix:

\( \begin{aligned}\mathbf{F}_{512} & = \mathbf{P}_{512}\left(\mathbf{F}_{256}\right)^{2}\mathbf{D}_{2,256} & \mbox{(decomposition stage 1)}\\ & = \mathbf{P}_{512}\left(\mathbf{P}_{256}\left(\mathbf{F}_{16}\right)^{16}\mathbf{D}_{16,16}\right)^{2}\mathbf{D}_{2,256} & \mbox{(decomposition stage 2)}\\ & = \mathbf{P}_{512}\left(\mathbf{P}_{256}\right)^{2}\left(\mathbf{F}_{16}\right)^{32}\left(\mathbf{D}_{16,16}\right)^{2}\mathbf{D}_{2,256} & \\ & = \mathbf{R}_{512}\left(\mathbf{F}_{16}\right)^{32}\left(\mathbf{D}_{16,16}\right)^{2}\mathbf{D}_{2,256} & \end{aligned} \)

Factorization of \( 1024 \)-point DFT matrix:

\( \begin{aligned}\mathbf{F}_{1024} & = \mathbf{P}_{1024}\left(\mathbf{F}_{256}\right)^{4}\mathbf{D}_{4,256} & \mbox{(decomposition stage 1)}\\ & = \mathbf{P}_{1024}\left(\mathbf{P}_{256}\left(\mathbf{F}_{16}\right)^{16}\mathbf{D}_{16,16}\right)^{4}\mathbf{D}_{4,256} & \mbox{(decomposition stage 2)}\\ & = \mathbf{P}_{1024}\left(\mathbf{P}_{256}\right)^{4}\left(\mathbf{F}_{16}\right)^{64}\left(\mathbf{D}_{16,16}\right)^{4}\mathbf{D}_{4,256} & \\ & = \mathbf{R}_{1024}\left(\mathbf{F}_{16}\right)^{64}\left(\mathbf{D}_{16,16}\right)^{4}\mathbf{D}_{4,256} & \end{aligned} \)

Factorization of \( 4096 \)-point DFT matrix:

\( \begin{aligned}\mathbf{F}_{4096} & = \mathbf{P}_{4096}\left(\mathbf{F}_{256}\right)^{16}\mathbf{D}_{16,256} & \mbox{(decomposition stage 1)}\\ & = \mathbf{P}_{4096}\left(\mathbf{P}_{256}\left(\mathbf{F}_{16}\right)^{16}\mathbf{D}_{16,16}\right)^{16}\mathbf{D}_{16,256} & \mbox{(decomposition stage 2)}\\ & = \mathbf{P}_{4096}\left(\mathbf{P}_{256}\right)^{16}\left(\mathbf{F}_{16}\right)^{256}\left(\mathbf{D}_{16,16}\right)^{16}\mathbf{D}_{16,256} & \\ & = \mathbf{R}_{4096}\left(\mathbf{F}_{16}\right)^{256}\left(\mathbf{D}_{16,16}\right)^{16}\mathbf{D}_{16,256} & \end{aligned} \)

Factorization of \( 8192 \)-point DFT matrix:

\( \begin{aligned}\mathbf{F}_{8192} & = \mathbf{P}_{8192}\left(\mathbf{F}_{4096}\right)^2 \mathbf{D}_{2, 4096} & \mbox{(decomposition stage 1)} \\ & = \mathbf{P}_{8192}\left(\mathbf{P}_{4096}\left(\mathbf{F}_{256}\right)^{16}\mathbf{D}_{16,256}\right)^2 \mathbf{D}_{2,4096} & \mbox{(decomposition stage 2)}\\ & = \mathbf{P}_{8192}\left(\mathbf{P}_{4096}\right)^2\left(\mathbf{F}_{256}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2 \mathbf{D}_{2,4096} & \\ & = \mathbf{P}_{8192}\left(\mathbf{P}_{4096}\right)^2\left(\mathbf{P}_{256} \left(\mathbf{F}_{16}\right)^{16}\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2 \mathbf{D}_{2,4096} & \mbox{(decomposition stage 3)}\\ & = \mathbf{P}_{8192}\left(\mathbf{P}_{4096}\right)^2\left(\mathbf{P}_{256}\right)^{32}\left(\mathbf{F}_{16}\right)^{512}\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2 \mathbf{D}_{2,4096} & \\ & = \mathbf{R}_{8192}\left(\mathbf{F}_{16}\right)^{512}\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2 \mathbf{D}_{2,4096} & \end{aligned} \)

The DFT computation is carried out by first multiplying the data vector by the sparse decomposition \( \mathbf{D} \) matrices (in as many stages as there are \( \mathbf{D} \) matrices in the final factorization), then multiplying the resultant data by the block diagonal DFT matrix \( \left(\mathbf{F}_{M,N}\right)^k \), and finally permuting the resultant data according to into the \( \mathbf{R} \) matrix.

For example, to compute DFT for a \( 8192 \)-point data vector \( \mathbf{f} \) - that is, to compute \( \mathbf{F}_{8192}\times \mathbf{f} \), we use the sparse factorization \( \mathbf{F}_{8192} = \mathbf{R}_{8192}\left(\mathbf{F}_{16}\right)^{512}\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2 \mathbf{D}_{2,4096} \) given above. The computation goes through different stages as follows:

1.Decomposition stage 1: \( \mathbf{D}_{2,4096}\times \mathbf{f} \)
2.Decomposition stage 2: \( \left(\mathbf{D}_{16,256}\right)^2\times\left(\mathbf{D}_{2,4096}\mathbf{f}\right) \)
3.Decomposition stage 3: \( \left(\mathbf{D}_{16,16}\right)^{32}\times\left(\left(\mathbf{D}_{16,256}\right)^2\mathbf{D}_{2,4096}\mathbf{f}\right) \)
4.DFTs' stage ( \( 16 \)-point DFTs): \( \left(\mathbf{F}_{16}\right)^{512}\times\left(\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2\mathbf{D}_{2,4096}\mathbf{f}\right) \)
5.Permutation: \( \mathbf{R}_{8192}\times\left(\left(\mathbf{F}_{16}\right)^{512}\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2\mathbf{D}_{2,4096}\mathbf{f}\right) \)

In the last step above, we see the permutation operation as \( \mathbf{R}_{8192}\times\left(\left(\mathbf{F}_{16}\right)^{512}\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2\mathbf{D}_{2,4096}\mathbf{f}\right) \), where \( \mathbf{R}_{8192} \) is the product of several permutation matrices - that is, \( \mathbf{R}_{8192} = \mathbf{P}_{8192}\left(\mathbf{P}_{4096}\right)^2\left(\mathbf{P}_{256} \right)^{32}\). To understand the effect of multiplication of data by \( \mathbf{R}_{8192} \) matrix, we illustrate what happens to the data when left-multiplied by the \( \mathbf{P} \) matrices taken one by one from right to left in the product \( \mathbf{R}_{8192} \).

The data vector input to the permutation operation is \( \left(\mathbf{F}_{16}\right)^{512}\left(\mathbf{D}_{16,16}\right)^{32}\left(\mathbf{D}_{16,256}\right)^2\mathbf{D}_{2,4096}\mathbf{f} \), which we denote as \( \mathbf{x} \). Assume the data content of \( \mathbf{x} \) is as follows. Note that there are \( 8192 \) data elements.

This data is to be left-multiplied first by the right-most permutation matrix, namely \( \left(\mathbf{P}_{256}\right)^{32} \). The effect of this multiplication \( \left(\mathbf{P}_{256}\right)^{32}\times \mathbf{x} \) is to form \( 32 \) groups of \( 256 \) elements each, and to count by \( 16 \)s in each group. The resultant data \( \left(\mathbf{P}_{256}\right)^{32}\mathbf{x} \) is shown below.

Then, the above data is to be left-multiplied by the next (going right to left in the product \( \mathbf{R}_{8192} \)) permutation matrix \( \left(\mathbf{P}_{4096}\right)^2 \). The effect of this multiplication \( \left(\mathbf{P}_{4096}\right)^2 \times \left( \left(\mathbf{P}_{256}\right)^{32}\mathbf{x}\right) \) is to form \( 2 \) groups of \( 4096 \) elements each, and to count by \( 256 \)s in each group. The resultant data \( \left(\mathbf{P}_{4096}\right)^2\left(\mathbf{P}_{256}\right)^{32}\mathbf{x} \) is shown below.

Finally, the above data is to be left-multiplied by the next permutation matrix \( \mathbf{P}_{8192} \). The effect of this multiplication \( \mathbf{P}_{8192}\times \left(\left(\mathbf{P}_{4096}\right)^2\left(\mathbf{P}_{256}\right)^{32}\mathbf{x}\right) \) is to count by \( 4096 \)s in the entire data vector. The resultant data \( \mathbf{P}_{8192}\left(\mathbf{P}_{4096}\right)^2\left(\mathbf{P}_{256}\right)^{32}\mathbf{x} \) is shown below.

Thus, the effect of multiplying \( \mathbf{R}_{8192} \) matrix and the \( 8192 \)-point data vector \( \mathbf{x} \) is to first count by \( 4096 \)s, then count by \( 256 \)s, then count by \( 16 \)s, and finally count by \( 1 \)s.

Following notes describe how the algorithm outlined above is implemented on C7x+MMA.

Each of the decomposition stages can be computed using C7x+MMA in two operations:

  • matrix multiplication on MMA between a dense matrix formed by choosing only the non-zero entries in the sparse \( \mathbf{D} \) matrix and a dense matrix formed by rearranging the data vector. The dense matrices corresponding to the \( \mathbf{D} \) matrices are prepared a priori by the FFTLIB_FFT_highRadixDecompositions_ixX_cxX_oxX_twGen function. For the data vector, the appropriate rearrangement is accomplished using the streaming engine.
  • point-wise multiplication on C7x to multiply "left-overs" from the \( \mathbf{D} \) matrix. This is required because the dense matrix multiplication on MMA does not completely accomplish the multiplication by the \( \mathbf{D} \) matrix. This operation piggybacks on the dense matrix multiplication, and hence does not consume many additional cycles.

Then, the DFTs' stage is accomplished on MMA as dense matrix multiplications. Each \( \mathbf{F}_{16} \) block of the \( \left(\mathbf{F}_{16}\right)^N \) block diagonal matrix forms one of the dense matrices, while data vector is rearranged into the other dense matrix. Rearrangement of data vector is accomplished by the streaming engine and the MMA in transpose mode.

The permutation operation does not take an additional computation stage. It merely piggybacks to the DFTs' stage, and does not take any additional cycles. This is accomplished by virtue of reading the data for DFTs' stage in the proper sequence using the streaming engine and storing the data in the proper sequence using the stream address generator.

The implementatation assumes the input complex data has its real and imaginary parts interleaved. If the input complex data is non-interleaved, the implementation employs an additional loop in the beginning to first interleave the input data, and an additional loop in the end to deinterleave the output data.
